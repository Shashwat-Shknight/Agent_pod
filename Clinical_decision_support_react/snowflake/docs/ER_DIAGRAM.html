Snowflake · NUUCARE_DB

NuuCare Data Model

Everything the Encounter Pod saves lives in one Snowflake database. A consultation becomes one row in CLINICAL.ENCOUNTERS, and every agent's output hangs off that row: the transcript, the SOAP draft and decision support, the codes, the signed note versions, the bill, its PDF and the claim. Nothing is kept in local files, and the record survives after the patient leaves.

What gets written when

One consultation, from the first word to the claim. Steps 1 to 3 all go through the stored procedure CLINICAL.UPSERT_ENCOUNTER, which writes the encounter and its child tables in one transaction and does nothing when the record's hash has not changed.

  1. Consultation recordedAmbient scribe turns the conversation into a SOAP draft.
    ENCOUNTERSENCOUNTER_HISTORYENCOUNTER_TRANSCRIPTSENCOUNTER_AI_OUTPUTS
  2. Decision support runsHarrison's passages retrieved per diagnosis, with the recommendations built from them.
    ENCOUNTER_AI_OUTPUTS.RETRIEVED_GUIDELINES.RECOMMENDATIONS
  3. Every later editNew ROW_VERSION on the encounter, and a full copy appended to its history.
    ENCOUNTERS.ROW_VERSIONENCOUNTER_HISTORY
  4. Doctor signs the noteAppend-only: signing or withdrawing adds a version, nothing is overwritten. The note goes to the coding queue.
    SOAP_NOTESENCOUNTERS.STATUS
  5. Coder accepts or rejects codesEach code is checked against the official release valid on the visit date.
    ENCOUNTER_CODESreads REFERENCE.CODES
  6. Send to RCMPriced lines go on the bill; open validation issues travel with it as RCM exceptions. The bill PDF is stored with its SHA-256.
    GENERATED_BILLS.BILL_JSONBILL_DOCUMENTS
  7. Claim generated and validated837P / 837I draft and its validation report; a regenerated claim soft-deletes the one it replaces.
    CLAIMSBILL_DOCUMENTS

At every step, the user's action is appended to SECURITY.AUDIT_LOG with who did it and when. In the background, a daily sync loads new ICD-10-CM (CDC) and HCPCS (CMS via NLM) releases into REFERENCE and records each attempt in SYNC_RUNS.

Design decisions

Full record plus typed columns

Each encounter keeps its complete record as VARIANT JSON, so no field is lost, and copies the fields people query (patient, status, assignee, dates) into typed columns.

History is append-only

Encounter versions, SOAP note versions and the audit log only ever gain rows. Any past state of a consultation can be read back.

Code sets with validity dates

Every ICD-10-CM and HCPCS code version has VALID_FROM and VALID_TO, so a claim is checked against the codes in force on the visit date, not today's list.

PDFs stored in the database

Bills and claims are saved as BINARY with a SHA-256 hash. The same document is never stored twice, and nothing depends on a local folder.

Least-privilege access

The app connects as a key-pair service user with role NUUCARE_APP. Schema changes run as NUUCARE_OWNER. Reporting can use NUUCARE_READONLY.

Cost guard

An extra-small warehouse that suspends after 60 seconds idle, under a resource monitor capped at 25 credits a month.
